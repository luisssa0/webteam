# ERROR 404 — интерактивный брендбук 

## Запуск

1. Откройте папку `error404-brandbook` в Visual Studio Code.
2. Установите расширение **Live Server** (если его нет).
3. Нажмите правой кнопкой на `index.html` → **Open with Live Server**.
4. Откроется адрес вида `http://127.0.0.1:5500/index.html`.

Не открывайте `index.html` через `file://`: ES-модули из локального файла часто блокируются политикой безопасности браузера. Live Server — это **локальная раздача статических файлов**, а не backend.

## Один объект данных на всю команду

В `state.js` находятся все обязательные поля:

```js
{
  name, slogan, audience, goal, character,
  paletteId, fontId, fontSize, fontWeight,
  layoutId, previewText
}
```

`DEMO_STATE` содержит пример: ERROR 404, аудитория 27–37 лет, слоган «Нормальность переоценена».

Палитры: `infrared`, `acid`, `crimson`.
Шрифты: `unbounded` (Unbounded), `plex` (IBM Plex Mono), оба с кириллицей.
Композиции: `offset`, `stacked`.

**Важно:** IDs (`infrared`, `acid` и т.д.) — часть общего контракта. Не меняйте их в одном файле без согласования с командой.

## Как обмен данными работает на практике

1. `main.js` вызывает `readDraft()` из `storage.js` и создаёт store через `createBrandStore()`.
2. Он вызывает `mountBrief(root, store)`, `mountColors(root, store)` и т.д.
3. Каждый модуль подписывается `store.subscribe(state => { ... })` и отображает данные.
4. При вводе участник вызывает `store.update({ slogan: '...' })` или другую частичную правку.
5. Store оповещает все модули. Одновременно `main.js` обновляет CSS-переменные и сохраняет полный объект в `localStorage`.
6. Если браузер запрещает хранение, работа продолжается в памяти; пользователь видит сообщение. Кнопка «Сохранить» может повторить попытку.
7. «Сбросить демо» удаляет ключ и возвращает исходные значения. После сброса последующие изменения снова сохраняются.

Все изменения применяются **без перезагрузки**. Каждый модуль работает с одним store, а не с локальными копиями состояния.

## Стили и источники

Референсы служат **стилевым направлением**: чёрная основа, световые красно-оранжевые акценты, бордовые варианты, кислотный лайм, огромный типографический масштаб, асимметричная модульная сетка. Самостоятельная CSS-графика вместо копирования чужих снимков и макетов.

Шрифты бесплатно загружаются из Google Fonts; при недоступности сети работают запасные системные шрифты. Для полностью офлайн-сборки команда может позже подключить локальные веб-шрифты с разрешённой лицензией.

## Проверка перед сдачей

- На Live Server открывается сайт без ошибок консоли.
- Кнопки навигации ведут к четырём разделам.
- Изменение слогана в брифе обновляет главный экран и макеты.
- Цветовая палитра меняет общие CSS-переменные и предпросмотры.
- Типографический блок меняет шрифт, размер, толщину и пример текста.
- Переключатель композиции работает на двух макетах.
- Перезагрузка страницы восстанавливает изменения (если localStorage доступен).
- Сброс удаляет черновик и показывает демоданные.
- Страница остаётся читаемой на мобильном экране и при 200% масштабе.

## Минимальные стандарты доступности

Для обычного текста ориентир WCAG AA — контраст не меньше 4.5:1; для крупного — 3:1. Не используйте один лишь цвет как индикатор состояния. Не удаляйте обводку `:focus-visible`.


## Печать и сохранение в PDF

Кнопка **«Печать / PDF»** открывает `window.print()` — системный диалог браузера, без сервера и отправки данных. Стили `@media print` в `common.css` скрывают редакторы, навигацию, настройки, кнопки, служебный статус и декоративные блоки. В печатной версии показываются актуальные поля брифа и **оба** макета (постер и карточка), каждый на отдельной странице.

1. Запустите `index.html` с Live Server или откройте опубликованную ссылку.
2. Измените слоган и название в «Брифе», выберите палитру, убедитесь в изменении обоих макетов.
3. Нажмите **«Печать / PDF»**. В предварительном просмотре ожидаются текстовый бриф и оба макета; поля ввода и настройки отсутствуют.
4. Выберите принтер или **Сохранить как PDF**. Формат — **A4, книжная ориентация**, масштаб — 100%, поля — по умолчанию. Включите опцию **Фоновая графика / Background graphics** для точных цветов.
5. Сохраните PDF, откройте его, проверьте, что весь текст читаемый, а оба макета присутствуют.
6. Закройте диалог и обновите страницу: при разрешённом localStorage введённые изменения должны сохраниться.

Если браузер запрещает localStorage, сайт остаётся работоспособным, но изменения не переживут обновление страницы. Печать всё равно работает.
